# 公式情報と鮮度の扱い

このファイルは、教材、画面名、製品仕様、リリース差、CSA試験情報を案内するときに参照する。

## 情報源の優先順位

次の順で確認し、より上位の公式情報とSkill内の記述が矛盾する場合は公式情報を優先する。

1. ServiceNow公式ドキュメント
2. ServiceNow University
3. ServiceNow Developer Site
4. ServiceNow公式Community
5. その他の情報源

検索結果の要約だけで判断せず、可能なら元の公式ページを開く。非公式情報は公式情報で確認できない補助説明に限り、非公式であることを明示する。

公式の探索起点として、[製品ドキュメント](https://www.servicenow.com/docs/)、[ServiceNow University](https://learning.servicenow.com/)、[Developer Site](https://developer.servicenow.com/)、[公式 Community](https://www.servicenow.com/community/) を使う。CSA の現在情報は University の [CSA Mainline Exam Blueprint](https://learning.servicenow.com/kb?id=kb_article_view&sysparm_article=KB0011554) を候補の起点にし、利用時に更新日と本文を再確認する。リンクが移動・認証要求・廃止になった場合は URL から事実を推測せず、同じ公式サイト内で名称を検索し直す。

## 確認が必要な情報

次を現在の事実として述べる前に、利用中リリースと公式情報を確認する。

- Application、Module、メニュー、ボタン、設定画面の名称とクリック順
- Role、ライセンス、プラグイン、製品エディションなどの前提条件
- Flow、Import、ACLなどのリリース依存の挙動
- ServiceNow Universityのコース名、日本語版の有無、公開状態、学習順
- CSAの出題領域、比重、問題形式、問題数、試験時間、合格条件、受験手順

カリキュラム中の用語・領域は学習の基準であり、現行試験仕様の保証ではない。特に数値や試験ポリシーを記憶から補完しない。

## 教材を案内する

1. ServiceNow Universityで対象概念の日本語コンテンツを先に探す。
2. 日本語版が確認できればそれを案内する。
3. 日本語版がなければ英語の公式コンテンツを案内し、日本語で学習ポイントを要約する。
4. コース名を確認できなければ、作り上げずに検索語と学ぶべき概念だけを示す。
5. 製品事実が教材と最新公式ドキュメントで矛盾する場合は、公式ドキュメントを優先し、差分を説明する。

## 操作を案内する

- まず目的、対象Record/Table、必要権限、成功確認を示す。
- 固定のクリック列より、Application Navigator等で探すための概念名・検索語を優先する。
- 学習者の画面と案内が違う場合は、リリース、UI、Role、導入済み機能の差を確認する。
- 確認できたUIだけを具体手順として示す。確認できない場合は候補を断定せず、学習者の画面情報を求める。

## 確認記録を残す

動的な事実を進捗や回答へ保存する必要がある場合は、少なくとも次を添える。

- 確認日
- 情報源の名称またはURL
- 対象リリース、UI、言語など判明している前提
- 確認できた事実と、未確認の点

過去の確認記録を永続的な真実として扱わない。次のセッションで現在性が重要なら再確認する。

## 確認できない場合

- 推測で穴を埋めず、「確認できていない」と明示する。
- 安定した概念説明と、公式サイトまたはInstance内での確認方法までは案内する。
- 正確な画面名や試験条件が必要なら、学習者に公式ページ、利用中リリース、または画面情報の共有を依頼する。
- 未確認情報をQuizの正答根拠や到達判定に使わない。
